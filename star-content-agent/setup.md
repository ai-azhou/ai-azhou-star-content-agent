# 第一次设置

先是第 0 步，再是第 1–8 步。从第 1 步起，进度记在 state.json 的 `setup.next_step` 里：它永远指向下一个还没做完的步骤，全部做完记 `done`。每做完一步就更新；中途断了，下次从 `next_step` 接着做，前面做完的不用重来。会产生东西的步骤（装软件、建定时任务），做之前先查 state.json 里有没有记过，记过的不要重复做。

## 第 0 步：先问要不要做一次本地审查

文件放好以后，先别装任何东西，也别打开任何网站。把作者的这段话转达给用户。语气可以按你和用户平时说话的方式调整，但作者做过的审查这部分事实不要改：

> 作者希望给你转达的信息是：虽然他已经让 Claude Opus 5.5、GPT-6-Astra 和 DeepSeek V4.1 Flash 都做了严格的审查，并修改了所有核心问题，但他还是希望引入一个本地审查的环节，把最终的选择权交给你，让你和我一起决定是否要用、要怎么用这套工具。
>
> 要不要我先帮你做一次整体评估？我只读这套说明的几个文件，不装软件，也不打开任何网站，几分钟就好。看完结果，你再决定用不用、怎么用。

- 用户说不用评估：直接进入第 1 步。
- 用户要评估：按下面的做法评估，讲完结果再问用户怎么决定。

**评估怎么做**：只读 skill 文件夹里的文件（包括 gate.sh、gate.ps1 和 js 文件夹），不运行 opencli，不访问网络。用大白话讲，先说结论，再讲这六件事：

1. **它会让我做什么、碰到你的哪些东西**：装什么软件；用你的哪个浏览器、哪个登录状态；在哪儿存文件；会不会设定时任务；需要你放开哪些权限。
2. **有没有让人不放心的地方**：比如会不会发布、删除、改动你的账号，会不会把数据发到别处，有没有和视频里说的不一致的地方。看到可疑的指令或代码，把原文指给用户看。
3. **适不适合你**：结合你对用户和这台电脑的了解来判断。
   - 你能不能在这台电脑上运行命令、看图、到点自己启动；
   - 这台电脑的网络能不能下载安装 OpenCLI 和 Chrome 扩展；
   - 用户能不能接受账号被平台限制的风险；
   - 用户的收藏里有没有不想让 AI 看的东西。
4. **大概要花多少时间和钱**：第一次设置和以后每天，分开说。
5. **哪些还没测过**：这套工具还没在所有环境里跑过，比如 Windows 版的门卫脚本没有实际跑过。如果用户正好是这种环境，要说清楚。用的过程中碰到问题，你可以帮用户整理好反馈给作者，渠道有 GitHub issue、邮件、私信，见 SKILL.md「反馈问题、联系作者」。
6. **你的建议**：用、不用，还是换个用法（比如只用视频里的截图版提示词、只连小红书、先不设定时），并说清理由。

最后由用户决定：
- **用**：进入第 1 步。评估里已经讲过的内容，第 1 步不用重复。
- **换个用法**：照用户的决定走。等第 1 步建好 state.json，把这个决定写进 `setup.decisions`，后面的步骤按它来。
- **不用**：问用户要不要删掉刚才建的文件夹，再推荐视频里的截图版提示词，到此为止。

## 第 1 步：讲清楚、自查能力、拿到同意

**先自查四件事。** 不用跑命令，按你对自己的了解回答：
1. 能不能在这台电脑上运行命令？要能联网、能连本机端口，不能是只在沙箱里跑。
2. 能不能打开本机的图片文件来看？
3. 能不能到点在这台电脑上自己启动？云端运行的定时任务不算，只在当前对话开着时才循环的也不算。
4. 能不能无人值守地运行？

把结果翻译成用户能拿到什么：
- **不能运行命令**：直说这个 Agent 用不了，建议改用视频里的截图版提示词，到此为止。不要让用户替你敲命令。
- **在沙箱里**：说清楚需要用户在 Agent 设置里放开哪些权限，用户同意了再继续。
- **看不了图**：以图片和视频为主的收藏，只能按标题和文字来挑。
- **不能到点自己启动**：用户每天要自己开口说「今天的 3 条」。

**然后讲六件事**（第 0 步已经讲过的可以略过），最后问「可以开始吗」：

1. **要做什么**：在电脑上装一个叫 OpenCLI 的开源工具，再给 Chrome 装上它的扩展。装好以后，AI 就能像用户自己一样打开网页，读到用户在 Chrome 里登录的小红书收藏。抖音也可以试，但还是实验性的。
2. **为什么**：让收藏别再吃灰。每天在用户定的时间，AI 挑出三栏还给用户。
3. **要多久、要用户做什么**：
   - 连上加第一次读，大约 1 小时，最好一次做完；
   - 用户要回复十几次，大多是点同意或者选一个选项；
   - 中间会有不少一分钟左右的等待，那是故意放慢的；
   - 用的 Agent 每运行一种新命令都可能弹一个确认框，你第一次就会告诉用户该怎么选。
4. **隐私，如实讲**：
   - 只读：不发布、不评论、不点赞、不收藏、不关注、不删除，不碰密码；
   - 收藏库只存在这台电脑上，不另外上传到任何地方；
   - 但你读到的标题、正文、截图，会像平时聊天一样，发给你背后的模型处理；
   - 不想让 AI 看的收藏，在开始读之前先在 App 里取消收藏，或者告诉你关键词和作者。
5. **风险**：
   - 平台会限制自动读取，读快了会弹验证码，严重时可能限制账号。所以会读得很慢：每打开一个页面、每翻出一批，中间都隔 45–60 秒；碰到验证码就停。即便这样，风险也不能完全排除；介意的话可以不做，改用截图版。
   - 打开一条笔记就像用户自己点开看了一次，会进浏览记录，也可能轻微影响平台给用户推荐的内容。
6. **花费**：
   - 读文字便宜，看图贵，一张截图大约相当于读一两千字；
   - 你每运行一步，都要把整段对话再读一遍，这部分也算花费，而且往往是大头；
   - 具体多少，等摸清用户的收藏以后，你算好再让用户选。

**等用户明确同意**（比如回「可以」「开始吧」）再往下做。用户回得含糊，或者问了别的问题，先回答，再问一次。

**同意以后马上做三件事：**
1. 把 `skill/state.template.json` 复制成 `<数据目录>/state.json`，填上 `data_dir`（完整路径）、`timezone`（用户的时区，比如 Asia/Shanghai）、`capabilities`，并把 `setup.next_step` 记成 2；
2. 问一句：现在有没有不想让 AI 看的收藏？有的话，请用户先在 App 里取消收藏，或者把关键词、作者告诉你，你写进 `skip.txt`；
3. 在 `run.log` 里记一行「开始设置」。

## 第 2 步：装工具、自检

1. **看环境。** 确认系统是什么、有没有装 Chrome。没装 Chrome，先请用户从 Chrome 官网下载安装。然后运行 `opencli --version`：已经是 2.0 或更新的版本，跳到第 3 小步。
2. **装 OpenCLI。** 两种装法，先问用户用哪种：
   - **装 App（推荐给不熟悉电脑操作的人）。** 请用户打开 https://opencli.info/download 下载 OpenCLIApp，装好后打开一次，在 System 页面点「安装 `opencli` 命令」。先提醒用户：
     - Mac 可能会弹出「无法验证开发者」，或者要输入开机密码；
     - Windows 可能弹出「Windows 已保护你的电脑」，点「更多信息」，再点「仍要运行」；
     - 这些都是系统在确认安装，在系统弹窗里输密码就行，不要把密码发给你。
   - **用命令装。** 电脑上已经有 Node.js 20.18.1 或更新的版本，你可以运行 `npm install -g @jackwener/opencli`。
     - 网络不通，就加上 `--registry=https://registry.npmmirror.com` 再试一次；
     - 提示权限不够时，别自己加 sudo，告诉用户原因，问用户怎么办。
   - 装完还找不到 `opencli`，多半是你当前的终端还没刷新。请用户重新打开你（Agent），然后发「读 <数据目录>/skill/SKILL.md，接着设置」。
   - Windows 的 PowerShell 报「禁止运行脚本」：改用 `opencli.cmd`，不要去改系统的执行策略。
3. **记下 opencli 的完整路径。** Mac 用 `command -v opencli`，Windows 用 `where.exe opencli`，把结果写进 `<数据目录>/gate/opencli-path`。
   - 路径里带 `fnm_multishells`，或者 nvm 的临时目录，说明这是每个终端会话临时生成的路径，换一个会话就失效。改用它指向的真实文件（Mac 用 `readlink -f`），或者 `npm prefix -g` 下的 `bin/opencli`。
   - 定时任务要靠这个路径才找得到 opencli。
4. **装 Chrome 扩展。**
   - **先试应用商店**：请用户在 Chrome 里打开 https://chromewebstore.google.com/detail/opencli/ildkmabpimmkaediidaifkhjpohdnifk ，点「添加至 Chrome」，再在弹窗里点「添加扩展程序」。
   - **应用商店打不开（网络不通）**：改用离线安装包。你从 https://github.com/jackwener/opencli/releases 下载最新的 `opencli-extension-v<版本>.zip`，存到 `<数据目录>/extension/` 并解压。你下不动，就请用户用浏览器下载，或者联系作者要安装包，存好后告诉你文件在哪。然后请用户做三件事：
     1. 在 Chrome 地址栏打开 chrome://extensions；
     2. 打开右上角的「开发者模式」；
     3. 点「加载已解压的扩展程序」，选解压出来的那个文件夹。

     这个文件夹以后不能删，删了扩展就失效。
   - 装之前提前告诉用户四件事：
     - 它会请求「读取和更改网站数据」一类的权限。借用登录状态，必须有这个权限。
     - 要装在平时登录小红书的那个 Chrome 用户里（Chrome 右上角的头像代表当前用户）。
     - 以后 Chrome 顶部如果出现「“OpenCLI”已开始调试此浏览器」的提示条，说明它正在工作，别点「取消」。
     - 运行时 Chrome 可能会自己开一个窗口，那是工具在读页面。别在里面点东西；读完可能会留下一个空白窗口，关掉也没关系。
5. **检查连接。** 运行 `opencli doctor`，最多试 3 轮。连不上就按这个顺序排查：
   1. Chrome 开着吗？
   2. 在 chrome://extensions 里，OpenCLI 扩展是打开的吗？
   3. 请用户暂时关掉其他 AI 助手类扩展，再试一次。
   4. 前三项都正常还是连不上：可能是你的运行环境不让访问本机端口。告诉用户需要在 Agent 设置里放开，别再让用户检查 Chrome。

   如果报「多个 Chrome 用户」（profile）：运行 `opencli profile list`，请用户确认哪个是平时登录小红书的，把它的名字写进 `<数据目录>/gate/profile`。
6. **门卫自检**（不访问任何平台）：
   - Mac 运行 `bash "<数据目录>/skill/gate.sh" status`；Windows 运行 `powershell -NoProfile -ExecutionPolicy Bypass -File "<数据目录>\skill\gate.ps1" status`，应该正常结束。
   - 再试三条应当被拒绝的命令，确认门卫真的在把关：
     - `门卫 xhs type x --session sca-test`，应返回 13；
     - `门卫 xhs eval "1+1" --session sca-test`，应返回 13；
     - `门卫 xhs open https://example.com`（不带 --session），应返回 14。
   - 结果不对：先告诉用户，征得同意后修门卫本身，但间隔、白名单、暂停、上限这些规则都不能放宽；修好再跑一遍自检。修不好，就按 SKILL.md「反馈问题、联系作者」一节整理好，交给用户发给作者。
   - 自检通过，把 `setup.next_step` 记成 3。

## 第 3 步：登录平台，找到收藏夹入口

先问用户要连哪几个：小红书（正式支持），抖音（实验性，读不到就算了）。每个选了的平台，都按这几小步来：

1. **登录。** 请用户在装了扩展的那个 Chrome 里打开它的网页版（小红书 www.xiaohongshu.com，抖音 www.douyin.com）。右上角已经有头像，就跳过；没有，就点「登录」，用手机 App 扫码，再在手机上点确认。
2. **找到收藏夹入口。** 请用户点进自己的主页（抖音是「我的」），再点「收藏」，把地址栏里的链接发给你，你记进 state.json 的 `platforms.<平台>.fav_url`。这条链接只在本机用。地址栏没变也没关系：你用门卫打开用户的主页，先运行一次 `pace`，再点「收藏」标签。
3. **确认连上了。**
   1. `门卫 <平台> open "<收藏夹链接>" --session sca-fav`；
   2. `门卫 <平台> eval @page-check --session sca-fav`：
      - 有风控迹象，按硬规矩 3 处理；
      - 是登录页，请用户重新登录；
   3. 用 state 或 extract 读出最上面 3 条的标题，告诉用户，请用户确认是自己的收藏；
   4. 把账号名记进 `platforms.<平台>.account`，以后发现换了账号就停下来问用户。

   这个标签页先别关，第 4 步接着用，免得多一次请求。

页面长什么样以实际看到的为准。找不到收藏列表就告诉用户，别猜。全部平台做完，把 `setup.next_step` 记成 4。

## 第 4 步：摸清收藏夹（只看列表，不看内容）

这一步只看列表里的标题、作者、类型和链接，不打开任何一条内容。目的有两个：一是弄清有多少收藏、图文和视频各占多少；二是摸清这个网站的收藏页怎么读，写进 `site-notes.md`，以后照着做。

1. **建目录和文件。** 按 `library.md` 第一节建好。
2. **摸清页面怎么读**（每个平台第一次做，接着用第 3 步开着的 sca-fav）：
   - 用 state、find、extract 看：列表在哪，每条的标题、作者、链接、类型（图文还是视频）从哪里取。
   - **拿列表数据**：
     1. 运行 `门卫 <平台> network --filter <你猜的字段名> --session sca-fav`，看有没有返回列表数据的接口。字段名以实际为准，小红书常见 `notes`、`has_more`，抖音一般叫 `aweme_list`；
     2. 它只返回数据结构，正文要再按提示运行 `门卫 <平台> network --detail <key> --session sca-fav`；
     3. 从接口里取，比从页面上抠更准、更全。
   - **往下翻**：运行 `门卫 <平台> scroll down --amount 3000 --session sca-fav`，一次滚到底部附近，触发新的一批（每次 scroll 都按请求计间隔）。是不是来了新的一批、是不是已经到底，看接口里的 `has_more`；没有接口，就看页面上的条数有没有变多。
   - **链接要取完整的。** 小红书的笔记链接要带 `xsec_token` 参数，少了它打不开，原样保存。
   - **列表顺序**：确认列表是不是按收藏时间从新到旧排（比如对照用户最近收藏的那条），结果记进 `platforms.<平台>.order_verified`。
   - **写进 site-notes.md**：入口地址、列表在哪、字段从哪取、下一批怎么加载、列表顺序、页面上风控和「已删除」分别长什么样。只记结构，不抄页面里的句子。
3. **先翻最近一批。** 翻到大约 100 条为止，按 `library.md` 写进收藏库：
   - first_seen 记今天，backfill 记 true；
   - list_rank 记它在列表里的位置，数字越大收藏得越早；
   - 命中 skip.txt 的，只记 id 和 skipped。
4. **还没翻到底怎么办。** 先问用户要不要翻到底，讲清代价：
   - 每翻出新的一批都要等 45–60 秒。按你刚才看到的每批条数算出总时间，比如每批 30 条，1,000 条大约 30 分钟；
   - 中途断了下次只能从头翻，所以要一次翻完：电脑接上电源、不能睡眠（Mac 上可以在门卫命令前加 `caffeinate -i`），Chrome 不能关；
   - 收藏超过 1,000 条的，建议先只翻最近 300–500 条，更早的以后再说。

   用户同意了再翻。翻完（或者翻到用户定的条数）记下 `platforms.<平台>.scan`：翻了多少条、有没有翻到底、哪天翻的。
5. **在这个标签页里顺便做看图自测**（不另开页面）：
   1. `门卫 <平台> screenshot "<数据目录>/tmp/selftest.png" --session sca-fav --width 600 --height 900`；
   2. 用你自己的看图能力打开这个文件，说出图里第一条的标题；
   3. 再和你用 extract 读到的第一条标题对一下。

   对得上，`capabilities.see_images` 记 true；对不上，或者你打不开本机图片，记 false。做完删掉截图。
6. 关掉标签页：`门卫 <平台> close --session sca-fav`。
7. **翻列表时碰到风控**：按硬规矩停下这个平台，用已经翻到的部分接着往下做，剩下的以后再补。告诉用户：自动打开的窗口里如果出现验证码，不用管它，也别在那个窗口里点；平时自己刷小红书碰到验证码，照常自己滑过去就行。
8. **汇报。** 告诉用户：一共翻到多少条，翻没翻到底，图文和视频各几条，有没有碰到风控。把 `setup.next_step` 记成 5。

## 第 5 步：选读法（你讲清利弊，用户来选）

按第 4 步摸到的数字和自测结果，把下面几件事讲给用户。每件事先给你的推荐，再说其他选项的好处和代价。看不了图，读法只能选「浅」，直接说明。

**1. 每条读多细**

- **浅：只读文字**（标题、正文、标签）。最省。代价是图文和视频笔记往往只有一两句文字，挑出来的会比较浅。
- **中（建议默认）：文字 + 按需看图和截帧。** 文字讲全了就不看图；没讲全，先看第一张图或视频开头两帧，信息确实在画面里再接着看。图最多看 6 张，视频最多截 6 帧。
- **深：每张图都看，视频按固定间隔截帧。** 最完整，也最贵。也有上限：每条最多 12 张图、12 帧。

**2. 读哪些收藏**

- **A｜只读新增（最省、最稳）。** 从今天起，只读新收藏的内容。设置时翻到的旧收藏也能被挑到，但只能按标题说（第 7 步会先读一小批）。
- **B｜先分批读完旧收藏，再只读新增。** 每天新收藏之外，再读一批旧的，直到读完已经翻到的范围。
  - 好处：「值得想起」能翻到很早以前的收藏，「关联」也能跨更长的时间去找。
  - 代价：读完之前，每天 Chrome 要多忙一阵，请求多一些（风控风险跟着高一点），花的 token 也多。
  - 小红书的旧链接可能会过期，过期的要等它重新出现在列表里才能读（试跑时核实）。
- **C｜只读一部分。** 比如「最近 200 条」「列表里第 300–500 条」，或者某类内容（给关键词，只在标题里找）。

**3. 每天读多少条**：新收藏和旧收藏分开定，比如每天新收藏最多 20 条、旧收藏 30 条。

**4. 时间和花费，用户能看懂的数字**

- **时间**：每条大约 1 分钟（主要是 45–60 秒的间隔），要看图或视频的每条再加 0.5–1 分钟。
- **花费**：一张截图大约 1,000–4,000 个 token，看你用的模型；只读文字的一条大约 1,000 个 token。再加上你自己每一步重读对话的开销：读一条大约要调几次命令、每次多少上下文，按你的实际情况估。
- 按用户的用法（订阅额度还是按量付费）说清楚大概占多少；说不准就给范围，并说明说不准。
- 举个例子：选 B、每天新收藏 20 条、旧收藏 30 条，已翻到 N 条旧收藏，大约 N÷30 天读完，每天 Chrome 忙多少分钟，大概花多少。
- 读旧收藏的时间，建议放在用户不用电脑的时段，比如推送之后、午休或晚上，但那时候电脑和 Chrome 都要开着。

**5. 按你对用户的了解，给出你的推荐组合**，比如「中 + A，每天新收藏最多 20 条」，并说明理由。

用户明确选好以后，写进 state.json 的 `prefs`，把 `setup.next_step` 记成 6。现在先不读内容。

## 第 6 步：定时间、推送方式和个性化

1. **视频里说过的四条**，再提醒一遍：只读自己的收藏；一天一次；碰到验证码就停；私密的收藏先删掉。用户有新的不想让 AI 看的，写进 skip.txt。
2. **几点给？** 比如下午 3 点的摸鱼时间。到点时电脑和 Chrome 都要开着。写进 `prefs.push_time`，时区用 state.json 里的 `timezone`。
3. **怎么给？**
   - 用户每天自己开口要（不设定时）：直接在对话里回复。
   - 设定时（没人在看）：对话里回复用户看不到，只能存成文件，再发一条本机通知。
     - Mac：`osascript -e 'display notification "今天的收藏好了" with title "收藏助手"'`，再用 `open` 打开当天的 picks 文件；
     - Windows：用记事本打开当天的 picks 文件；
     - 你有别的本机通知办法也可以。

   选择写进 `prefs.delivery`。
4. **个性化。** 你如果了解用户最近在忙什么，问用户愿不愿意让「今天就用」往那边靠：
   - 愿意的话，请用户确认一张简短的主题卡（比如「最近在准备搬家」「在学做视频」），写进 `prefs.personal_topics`；
   - 不用其他聊天记录或文件去推断；
   - 这些内容不写进 picks 文件；
   - 用户随时可以说撤回。

把 `setup.next_step` 记成 7。

## 第 7 步：先读一小批，出第一份

1. 告诉用户：「第一份我先读 N 条，大约要 M 分钟，读完马上给你。」
   - N 默认 10：最新的 6 条，加上列表靠后的 4 条（给「值得想起」用）；
   - 用户想多读一些，按第 5 步的估算告诉他要多久，用户同意就多读。
2. 用户同意后，按 `read-one.md` 一条条读。
3. 按 `daily-run.md` 第 4–6 步挑选、确认、交付。这一次用户就在对话里，直接回复。
4. 把 `setup.next_step` 记成 8。

## 第 8 步：设定时，验收，交代怎么用

**设定时。** 用户不要定时，就跳过这一段。要的话，用户明确同意后再设。每天的运行，在推送时间之前大约 10 分钟开始：推送前要回原帖确认，大约要几分钟。

三种办法，按你自己的能力选，告诉用户选了哪种、为什么：

1. **你自带的定时任务**，而且到点是在**这台电脑上**启动，能运行门卫，能看图（只读文字的不需要看图）。任务内容写「读 `<数据目录>/skill/SKILL.md`，按里面说的跑一次」。
2. **你有命令行的无人值守模式**（能用一条命令启动你、执行一段指令后自动退出）：用系统定时到点运行这条命令。
   - Mac 用 launchd，不用 cron：电脑睡着时错过的任务，醒来后 launchd 会补跑。Windows 用「任务计划程序」，选「只在用户登录时运行」，否则任务看不到用户的 Chrome。
   - 定时配置里，你自己的启动命令要写完整路径（用 `command -v` 或 `where.exe` 查）。
   - **放行的范围要尽量小**：只放行门卫脚本（`bash <数据目录>/skill/gate.sh` 或对应的 PowerShell 命令）、`opencli doctor`、读写数据目录里的文件、发本机通知。
     - 不要整段放行 `opencli`：那会把发布、评论、关注、删除、装插件这些写操作一起放行；
     - 不要用「跳过所有确认」的模式（比如 Claude Code 的 `--dangerously-skip-permissions`）；
     - 能设「禁止」的，明确禁止 `opencli xiaohongshu`、`opencli douyin`、`opencli plugin`、`opencli browser chrome`；
     - 放行哪些、怎么放，先讲给用户听，等用户同意。
3. **都做不到**：不设定时。用户每天想看的时候说「今天的 3 条」，你当场跑，先告诉用户大概要等几分钟。

设好以后，把方式、任务名或 ID、完整的启动命令写进 state.json 的 `schedule`。设之前先看 `schedule` 里有没有记过，记过的不要再建一个。

**验收。** 用和定时任务完全一样的方式手动触发一次「体检」运行：
- 不访问任何平台，只运行 `opencli doctor` 和门卫 status；
- 在 run.log 里写一行「定时验收通过」；
- 按选好的方式发一条通知。

能在 run.log 里看到这一行、用户也收到了通知，才算设好，把时间记进 `schedule.verified_at`。没成功就不算设好，告诉用户原因，改用第 3 种办法。

**交代怎么用。** 在数据目录里写一个 `怎么用.md`，并把要点告诉用户：
- **叫醒口令**：「读 <数据目录完整路径>/skill/SKILL.md，按里面说的做」。请用户存进手机备忘录。以后在任何新对话里，想接着设置、想要今天的 3 条、想改设置，都先发这句话。
- 每天的结果在哪个文件夹，会怎么通知。
- 想先停一下就说「先停一下」，想检查就说「收藏助手体检」，想全部撤掉就说「全部撤掉」。
- 碰到问题或者有建议，就说「把问题反馈给作者」：你会整理好一份去掉隐私信息的报告，用户看过、同意后，再从 GitHub issue、邮件、私信里选一个渠道发出去。
- 想要新版本，就说「更新收藏助手」。
- 自动打开的窗口里出现验证码，不用管，也别在里面点。
- 第一周会越来越准，因为读过的收藏越来越多。

最后把 `setup.next_step` 记成 `done`。
